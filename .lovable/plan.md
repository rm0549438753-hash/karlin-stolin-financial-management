## הבעיה
לוגים בשרת מראים:
```
Error: Worker exceeded memory limit. (HTTP 502)
```
כלומר הגיבוי נופל כי ה-Worker חורג ממגבלת הזיכרון. הקוד הנוכחי בונה את כל ה-CSV של כל טבלה בזיכרון (כולל `transactions` עם ~9,000 שורות ועמודות רחבות) לפני העלאה, וגם אוסף את כל הטבלאות ברצף באותה קריאה. בנוסף, כי השרת נופל ב-502 לפני שהקוד מספיק לכתוב `error_message`, הריצה נשארת במצב "running" והלקוח רואה רק "Internal server error" גנרי.

## התכנית

### 1. גיבוי כתהליך רקע (background job)
- הפעלה ידנית תחזיר מיידית `{ ok: true, runId }` אחרי יצירת שורת `backup_runs` עם `status='running'`, ותפעיל את `runBackup` דרך `waitUntil` (או שרת-רוט ייעודי) כדי לא לחסום את בקשת ה-HTTP ולא לחרוג מזיכרון-בקשה.
- ה-cron יעבוד באותה שיטה.

### 2. הורדת שימוש בזיכרון ב-`backup.server.ts`
- לא לשמור בזיכרון את כל ה-CSV של טבלה גדולה. במקום זה: לפצל טבלאות גדולות (`transactions`, `action_history`) לחלקים של 1000 שורות, ולהעלות כל חלק כקובץ נפרד (`transactions-part-01.csv`, וכו') מיד אחרי בנייתו, ואז לשחרר את המחרוזת.
- לצמצם דילוגי `select("*")` על `action_history` (טבלה שיכולה להיות עצומה) ע"י דילוג עמודות `old_data`/`new_data` המכילות JSON גדול — או פיצול נפרד עבורה.
- להשתמש ב-`Uint8Array` ישירות לכל chunk במקום קונקטנציה של מחרוזת ענקית.

### 3. שיפור דיווח שגיאות
- בכל `catch` (כולל בשלב ההתחלה) לעדכן את `backup_runs` עם השגיאה המלאה (500 תווים ראשונים).
- הוספת timeout ב-catch של הלקוח: אם הריצה עדיין `running` יותר מ-5 דקות — לסמן `failed` עם "timeout".
- הלקוח יטען דרך polling אוטומטי כל 3 שניות כל עוד יש שורה במצב `running`.

### 4. עדכון פאנל הגיבוי (UI בעברית)
בטבלת "ריצות אחרונות":
- טור **סטטוס** ברור: "✓ הושלם בהצלחה" (ירוק), "✗ נכשל" (אדום), "רץ..." (כתום, עם ספינר).
- טור **שגיאה** מציג את `error_message` במלואו בכרטיסיה קריאה (לא רק tooltip) עם רקע אדום עדין.
- לכל ריצה מוצלחת — כפתור "פתח תיקייה" ישיר לתיקיית התאריך (`file_id`).
- למעלה בכרטיס העליון: כפתור "פתח תיקיית גיבויים ראשית" (`folder_id`).
- אחרי הפעלה ידנית: toast "הגיבוי מתחיל ברקע..." מיד, וההתקדמות מתעדכנת בטבלה אוטומטית עד ההשלמה.

## פרטים טכניים
- `src/lib/backup.server.ts`: פיצול `exportTable` לפאנצ'ים; העלאה מיד ולא צבירה. הפחתת `PAGE` ל-500 עבור `transactions` ו-`action_history`. הסרת שדות כבדים מ-`action_history` (או פיצול לקבצים לפי חודש).
- `src/lib/backup.functions.ts`: `triggerBackupNow` יוצר `backup_runs` row → מפעיל `runBackup` עם `runId` קיים דרך `waitUntil` → מחזיר מיידית `{ runId }`.
- `src/routes/api/public/hooks/daily-backup.ts`: אותו דפוס `waitUntil`.
- `src/components/BackupPanel.tsx`: עיצוב מחדש של טבלת הריצות עם הצגת שגיאה מלאה וכפתור "פתח תיקייה" לכל שורה.

## התוצאה המצופה
- הגיבוי יסתיים ברקע גם אם ה-request עצמו יסתיים.
- כישלון = יוצג מפורט (איזו טבלה נפלה ומדוע) בטבלת הריצות.
- הצלחה = כפתור ישיר לתיקיית הגיבוי הספציפית שנוצרה.
